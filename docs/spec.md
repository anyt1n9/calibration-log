# 予測の答え合わせアプリ — 仕様書

自分の予測に確率を添えて記録し、期限が来たら答え合わせをする。
溜まった記録から「自分の確信度がどれだけ当てにならないか」を曲線で見せる。

---

## 1. 何のアプリか

### 一文で

**70% と言ったとき、自分は本当に70%当てているのか。それを測る。**

### 解きたい問題

人は自分の予測精度を知らないまま予測し続ける。
「たぶん大丈夫」「まず間に合う」と言い、外れたら忘れる。当たったものだけ覚えている。

記録を取れば分かるはずだが、普通の日記では分からない。
**確率を数字で添えた時点で初めて、答え合わせが可能になる。**

### 他の記録アプリと違う点

| | 普通のメモ/日記 | このアプリ |
|---|---|---|
| 入力 | 思ったことを書く | 思ったこと **＋ 確率** |
| 後で | 読み返す | **○×を付ける** |
| 出力 | 記録の山 | **自分の癖を示す曲線** |

記録することが目的ではない。**答え合わせの瞬間に発生する気まずさ**が、このアプリの提供物である。

---

## 2. 中核となる体験

3つの瞬間しかない。ここ以外に機能を足さない。

### 瞬間1: 予測する（所要15秒）

文を書き、確率を選び、期限を決める。それだけ。
ここで悩ませてはいけない。15秒を超えると人は記録をやめる。

### 瞬間2: 期限が来る

ホームの最上段に**判定待ちが積み上がる**。
未判定が溜まるほど他の表示を押しのけ、視界の邪魔になる。これは意図的である。
「判定しないと使えない」状態を作ることで、記録の放置を防ぐ。

### 瞬間3: 答え合わせる（所要3秒）

○か×を押す。押した直後、**曲線がその場で動く**。
自分が動かした点が一瞬強調され、「80%の列が、また下がった」が体感される。

> **この瞬間のためだけにアプリを作る。**
> 入力画面も一覧画面も、すべてこの3秒に人を連れてくるための導線にすぎない。

## 3. 設計上の決定と、その理由

実装中に「こうしたほうが親切では」と感じても、以下は変えないこと。理由をここに書く。

### 3-1. 確率はスライダーにしない

**プリセットボタン（50 / 60 / 70 / 80 / 90 / 95）＋ ± ボタンで微調整。**

- スライダーは指を止めた場所が値になり、「なんとなく73%」を大量生産する
- 刻みが細かいと後のバケット集計で潰れ、粒度が見せかけだけになる
- 6択なら**選ぶ行為が思考になる**。「70か80か」で一度立ち止まる

### 3-2. 確率は 50〜99 のみ。50未満を入力させない

「起きないと思う」ときは、**文のほうを否定形で書く**。

- ○「今月中に終わる」30% → ✕
- ○「今月中に終わらない」70% → ○

理由: 50未満を許すと、曲線を描くときに内部で反転処理が必要になり、
ユーザーが見ている数字と集計されている数字がズレる。
**画面上の70%と、集計上の70%は常に同じものであるべき。**

入力欄のプレースホルダで書き方を案内する。

### 3-3. 「どちらとも言えない」は用意する。ただし記録に残す

判定は ○ / ✕ / **判定不能** の3択。
判定不能は集計から除外するが、**件数は画面に出し続ける**。

理由: 逃げ道がないと、判定が曖昧な予測を人は削除する。
削除されると記録自体が消えて何も残らない。
逃げ道は用意し、しかし**逃げた回数は見せる**。

### 3-4. 誤差帯を必ず描く（最重要）

キャリブレーション曲線の各点に、**Wilson score interval による誤差帯**を描く。

理由: n=3 で3回当たれば的中率100%になる。
これを点だけで描くと「自分は90%帯で完璧だ」という**嘘の確信**が生まれる。
誤差帯を描けば、n=3 の点は上下に大きく広がり、**「まだ何も言えない」が一目で分かる**。

このアプリが数字で嘘をつかないための、唯一の仕掛けである。省略してはいけない。

```
中心 = (x + z²/2) / (n + z²)
半幅 = z / (n + z²) × √( x(n−x)/n + z²/4 )
  x = 的中数, n = 判定済み件数, z = 1.96（95%信頼区間）
```

### 3-5. 総合スコアを主役にしない

Brier score は出すが、**画面の隅に小さく置く**。曲線が主役。

理由: 単一スコアを大きく出すと「スコアを上げるゲーム」になる。
スコアを上げる最短手は**確信度50%で予測し続けること**であり、それは何も学ばない。
測るべきは精度ではなく**歪みの形**なので、形が見える曲線が主役でなければならない。

### 3-6. 数字は1つだけ大きく出す — 「自信過剰度」

```
自信過剰度 = 平均確信度 − 実際の的中率
```

平均78%と言い、実際は64%なら **+14pt**。
これが最も刺さる1行であり、アプリを開く理由になる。

プラスなら「自信過剰」、マイナスなら「自信不足」と言い切る。ぼかさない。

### 3-7. 予測文を後から編集させない

作成後に編集できるのは**期限だけ**（延期は可、記録に残る）。
文と確率は確定したら変えられない。

理由: 編集できると、外れそうになったとき人は文を弱める。
**過去の自分を守れてしまうと、このアプリは何も測れなくなる。**

## 4. 画面

2画面のみ。タブで切り替える。

### 画面A: ホーム

```
┌─────────────────────────────┐
│  自信過剰度  +14pt          │ ← 判定が10件未満のときは非表示
│  「あなたは 78% と言い、     │
│    実際は 64% 当てている」   │
├─────────────────────────────┤
│  ▼ 答え合わせ（3件）         │ ← 期限到来。最上段に積む
│  ┌───────────────────────┐  │
│  │ 今月中に原稿が終わる   │  │
│  │ 80% · 3日前に期限      │  │
│  │  [○ 当たった] [✕ 外れ] │  │
│  │  [判定できない]        │  │
│  └───────────────────────┘  │
├─────────────────────────────┤
│  ＋ 新しい予測              │ ← 常にここ。1タップで入力へ
├─────────────────────────────┤
│  進行中（12件）              │
│  ・来週までに返事が来る 60% │
│    あと4日                  │
│  ・…                        │
└─────────────────────────────┘
```

- 判定待ちがある限り、**進行中リストより上**に居座る
- 判定待ちが0件のときだけ、上部がすっきりする（これが報酬になる）

### 画面B: 記録

```
┌─────────────────────────────┐
│   キャリブレーション曲線     │
│                             │
│ 実 100│           ╱         │
│ 際  90│         ╱ ┃         │ ← 縦棒が誤差帯
│ の  80│       ╱  ●┃         │
│ 的  70│     ╱  ┃●           │
│ 中  60│   ╱   ●┃            │
│ 率  50│ ╱    ┃              │
│      └────────────────────  │
│       50 60 70 80 90 100    │
│          確信度             │
│                             │
│  ╱ = 完璧な予測者の線        │
│  ● = あなた（棒は95%信頼区間）│
├─────────────────────────────┤
│  判定済み 47件 / 判定不能 5件│
│  Brier score 0.19           │ ← 小さく
├─────────────────────────────┤
│  履歴（新しい順）            │
│  ○ 80% 今月中に原稿が…      │
│  ✕ 90% 会議は30分で終わる    │
│  …                          │
└─────────────────────────────┘
```

### バケット

`50-59 / 60-69 / 70-79 / 80-89 / 90-100` の5つ。

細かく割らない理由: 個人の記録は年間でも数十〜数百件。
10バケットに割ると各点の n が一桁になり、誤差帯だらけで形が読めない。

## 5. 演出

**判定ボタンを押した瞬間に、全部が一斉に更新されてはいけない。**

```
[○ 当たった] を押す
  ↓ 0.0s  カードが○の色に変わる
  ↓ 0.3s  カードが判定待ちの山から抜けて消える
  ↓ 0.6s  記録タブにバッジが付く（見ていない場合）
  ↓ 0.9s  曲線を開くと、動いた点が一度だけ強調される
```

順に時間をかけて反映する。
**どの数字が自分の一押しで動いたのか**が分かることが、演出の目的である。

装飾・アニメーション・イラストで「アプリらしさ」を出そうとしないこと。
気持ちよさは**自分の行為と数字の変化が繋がって見えること**からしか生まれない。

## 6. データ

```ts
type Outcome = 'hit' | 'miss' | 'void'   // 当たり / 外れ / 判定不能

type Prediction = {
  id: string
  statement: string        // 予測文。作成後は変更不可
  confidence: number       // 50-99 の整数。作成後は変更不可
  createdAt: string        // ISO8601
  resolveAt: string        // ISO8601（日付のみ）。延期可
  postponedCount: number   // 延期回数。3回を超えると警告を出す
  tags: string[]           // フェーズ1では保存のみ。絞り込みは作らない
  outcome: Outcome | null
  resolvedAt: string | null
  note: string | null      // 判定時の一言（任意）
}
```

### 保存

`localStorage` のみ。サーバーもアカウントも作らない。

- キー: `calibration-log/v1`
- 起動時に読み、変更のたびに全体を書き戻す（件数が数千の規模では十分）
- スキーマ変更に備え、保存データの先頭に `version` を持たせる

### 書き出し / 読み込み

JSON のダウンロードと読み込みを付ける。
**localStorage はブラウザのデータ消去で消える。** 消えると全てを失うアプリなので、
これは「あると便利」ではなく必須機能として扱う。

## 7. 技術方針

- React + Vite + TypeScript
- 状態管理は `useReducer`。外部ライブラリは入れない
- **グラフは SVG を直接記述する。**チャートライブラリは使わない
- 定数は `src/config/constants.ts` に集約（バケット境界、z値、最小表示件数、演出の遅延時間）
- ダークモード対応。色は CSS 変数で定義し、ハードコードしない
- 表示する数値は必ず `Math.round()` か `.toFixed()` を通す
- 日付の計算に外部ライブラリを使わない。`Date` と自前のユーティリティで足りる範囲に留める

### 統計計算の分離

`src/lib/calibration.ts` に純関数として切り出す。
UIから独立させ、テストできる形にしておく。

```ts
bucketize(predictions): Bucket[]
wilsonInterval(hits, total): { center, low, high }
brierScore(predictions): number
overconfidence(predictions): number
```

## 8. フェーズ1の完成条件

**フェーズ1のみを実装する。指示があるまでフェーズ2に着手しない。**

- [ ] 予測の作成（文・確率プリセット・期限）が15秒で終わる
- [ ] 期限到来分がホーム最上段に積み上がる
- [ ] ○ / ✕ / 判定不能 の3択で判定できる
- [ ] キャリブレーション曲線が**誤差帯つき**で描画される
- [ ] 自信過剰度が1行で表示される（判定10件未満では非表示）
- [ ] 判定時に段階的な更新演出が入る
- [ ] localStorage に保存され、リロードで消えない
- [ ] JSON の書き出し・読み込みができる
- [ ] ダークモードで破綻しない

### 動作確認の方法

期限が来ないと何も確かめられないので、**開発時のみ**次を用意する。

- ダミーデータ生成（意図的に自信過剰な50件を作る）
- 「今日の日付」を進めるデバッグ操作

本番ビルドには含めない。

## 9. フェーズ1で作らないもの

| 機能 | 理由 |
|---|---|
| タグでの絞り込み・タグ別曲線 | 面白いが、まず全体の曲線が刺さるかを先に確かめる |
| 通知・リマインダー | Web Push は実装量が大きい。開いたときに気づけば十分 |
| 予測の共有・公開 | 人に見せる前提だと、記録が正直でなくなる |
| AI による予測文の補助 | 入力の15秒は既に十分短い |
| 複数ユーザー・同期 | サーバーが必要になる |
| 時系列での精度推移グラフ | 曲線が機能してから考える |

**核が面白いかどうかを先に確かめる段階である。**
