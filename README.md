# 予測の答え合わせ（calibration-log）

**70% と言ったとき、自分は本当に70%当てているのか。それを測る。**

自分の予測に確率を添えて記録し、期限が来たら ○ か ✕ を付ける。溜まった記録から、確信度と実際の的中率のズレを曲線で見せる。

## これは何を測るのか

的中率ではなく、**確信度の目盛りが合っているか**を測る。

- 「60%」と言って6割当たる人 → **満点**。4割外していても完璧
- 「95%」と言って7割しか当たらない人 → **失格**。よく当たっているのに失格

当たる回数の多さは問われない。問われるのは、自分が「かなり確実だ」と感じたときの *かなり* が実際に何%を指しているか。

タスク管理アプリではない。集計の軸は日付ではなく確信度で、「今日は何件できたか」は表示しない。

## 使い方

1. 予測を書き、確率（50〜95%）と期限を選ぶ。15秒で終わる
2. 期限が来ると、ホームの最上段に判定待ちが積み上がる
3. ○ か ✕ を押す。曲線がその場で動く

起きないと思うことは「〜しない」と否定形で書く。確信度は常に50%以上になる。

## 動かす

```bash
npm install
npm run dev
```

記録はブラウザの localStorage にのみ保存される。サーバーもアカウントもない。JSONで書き出せるので、ときどき保存しておくこと。

## 設計で守っていること

**誤差帯を必ず描く。** n=3 で3回当たれば的中率は100%になる。点だけを描くと「90%帯は完璧だ」という嘘の確信が生まれるので、Wilson score interval による帯を重ねている。n=3 の帯は 43.8%〜100% まで広がり、「まだ何も言えない」が一目で分かる。

**総合スコアを主役にしない。** Brier score は隅に小さく置くだけ。大きく出すと「スコアを上げるゲーム」になり、その最短手は全部50%と言い続けることになる。測りたいのは精度ではなく歪みの形なので、曲線が主役でなければならない。

**予測文を後から編集させない。** 外れそうになると人は文を弱める。過去の自分を守れてしまうと何も測れない。変更できるのは期限だけで、延期回数は記録に残る。

詳細は [docs/spec.md](docs/spec.md)、実装時に仕様から変えた点は [docs/changes.md](docs/changes.md) にある。

## 構成

React + Vite + TypeScript。状態管理は `useReducer` のみ、チャートライブラリなし（SVG直書き）。
